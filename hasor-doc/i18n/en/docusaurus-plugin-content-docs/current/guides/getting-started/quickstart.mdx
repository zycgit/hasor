# Quick Start

The current Hasor codebase is centered on `hasor-core`, `hasor-web`, and `hasor-boot`. Ordinary Java applications start with `hasor-core`; Web MVC applications add `hasor-web`; executable Fat Jar or embedded-container applications add `hasor-boot`.

:::info Runtime Requirements
Starting with the next version, Hasor is expected to move to the `5.0.0` line and support only JDK 17 or later. New projects should use JDK 17+.
:::

## Add hasor-core

The current source version is `5.0.0-SNAPSHOT`. Replace it with the released Maven Central version when using a stable release.

<Tabs>
  <TabItem value="Maven" label="Maven" default>

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-core</artifactId>
    <version>5.0.0-SNAPSHOT</version>
</dependency>
```

  </TabItem>
  <TabItem value="Gradle" label="Gradle">

```text
implementation "net.hasor:hasor-core:5.0.0-SNAPSHOT"
```

  </TabItem>
</Tabs>

## Create the container

The minimal startup path is one line:

```java
import net.hasor.core.AppContext;
import net.hasor.core.Hasor;

AppContext appContext = Hasor.create().build();
```

An application can create multiple independent `AppContext` instances, although most processes only need one main context.

## Write a Module

The configuration entry point is `net.hasor.core.Module`. Use `ApiBinder` inside `loadModule` to declare beans, SPI listeners, scopes, AOP, and other capabilities.

```java
import net.hasor.core.ApiBinder;
import net.hasor.core.Module;

public class AppModule implements Module {
    @Override
    public void loadModule(ApiBinder apiBinder) {
        apiBinder.bindType(HelloService.class).toInstance(new HelloService());
    }
}
```

Load the module during startup:

```java
AppContext appContext = Hasor.create().build(new AppModule());
HelloService helloService = appContext.getInstance(HelloService.class);
```

Modules can install other modules:

```java
public class RootModule implements Module {
    @Override
    public void loadModule(ApiBinder apiBinder) throws Throwable {
        apiBinder.installModule(new UserModule());
        apiBinder.installModule(new WebFeatureModule());
    }
}
```

## Load configuration

By default, Hasor reads `hconfig.xml` from the classpath. To use another file name, specify it during startup:

```java
AppContext appContext = Hasor.create()
        .mainSettingWith("my-hconfig.xml")
        .build(new AppModule());
```

You can also set configuration entries directly:

```java
AppContext appContext = Hasor.create()
        .addSettings("hasor", "app.name", "demo")
        .build(new AppModule());
```

## Choose Web or Boot

For Web MVC applications, add `hasor-web`:

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-web</artifactId>
    <version>5.0.0-SNAPSHOT</version>
</dependency>
```

For executable Fat Jar applications, use `hasor-boot-maven-plugin` and choose one embedded container module when needed:

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-boot-tomcat</artifactId>
    <version>5.0.0-SNAPSHOT</version>
</dependency>
```

Web Boot applications can start with `WebServers.run(args, RootModule.class)`. See [Packaging and Deployment](../deployment/overview.md), [Project Configuration](../deployment/project-config.md), and [Web Launcher](../deployment/web-launcher.md) for details.
