# v5.2.0 (2026-09-12)

## Scope

- Core, Config, Web, and Boot.

## Changes

- Added
  - Adds `hasor-boot` as a unified entry point for ordinary and Web applications.
  - Adds automatic Action result rendering with Jackson, Gson, Fastjson, and Fastjson2 support.
  - Adds `WebApiBinder.addResource(...)` for static resources, welcome files, and route fallbacks.
  - Adds a configurable `/health` endpoint to Boot Web.
  - Adds configurable redirect status codes to `@RedirectTo`.
- Improved
  - Moves `@Aop` into Core and unifies configuration scanning with route conflict detection.
  - Integrates rendering into request execution and adds HEAD and cache validation for static resources.
  - Unifies configuration, startup, and shutdown across Tomcat, Jetty, and Undertow.
  - Standardizes Core and Web logging on Cobble.
  - Expands Chinese and English documentation and historical release notes.
- Fixed
  - Prevents duplicate rendering for manually handled, asynchronous, committed, 204, and 304 responses.
  - Fixes early logging initialization in executable archives.
  - Fixes resource URL resolution for nested JARs without directory entries.

## Upgrade notes

- Use `net.hasor.config.ConfigurationModule` for auto-configuration and `hasor.loadPackages` for scanning.
- Action results are rendered automatically; set the corresponding default engine to `none` for manual handling.
- Register resources through `addResource(...)` and update access control: static resources no longer pass through Hasor business filters.
- Update package references for rendering, CORS, and AOP types, and remove old `RenderWebPlugin` registration.
- Move embedded server settings to `hasor.boot.web`, retain exactly one Web container implementation, and configure health checks as needed.
