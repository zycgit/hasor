# v5.3.0 (Unreleased)

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-web</artifactId>
    <version>5.3.0</version>
</dependency>
```

## Changes

- New Features
  - Support method-level `@MappingTo`, optional class-level path prefixes, and automatic discovery. Routes can share a path with different HTTP methods, with conflicts checked at startup.
  - Add `HandlerInterceptor` and `WebApiBinder.bindInterceptor(...)`, with pre-handlers in registration order and post-handlers and completion callbacks in reverse order. Config provides `WebMvcConfigurer.addInterceptors(...)`.
  - Add `ExceptionHandler`, `WebApiBinder.addExceptionHandler(...)`, and `@Exception` factory registration, selecting the most specific exception type and supporting dependency injection, scopes, and lifecycle management.
  - Add `Invoker.setSkipRender()` and `isSkipRender()` to skip result rendering for the current request.
  - Add typed `CacheControl` policies for static resources, supporting cache durations, shared/private caching, and chained directives.
  - Support `@Inject` on `@Bean` factory parameters to resolve dependencies by name and type, or by binding ID.
- Bug Fixes
  - Fix unreferenced singleton `@Bean` factories and their `initMethod` callbacks not running during startup.
  - Render exception handler results from void Actions.
  - Clear the parameter cache when requests end, and fix a null-pointer error when resolving the content type without a matched Action.
  - Restore the Web URL log in the unified Boot entry point and correctly handle the bound port, context path, and IPv6 addresses.
- Improvements
  - Use one rendering path for normal return values, results changed by interceptors, and exception handler results. Load interceptor and exception handler registrations when the Web context initializes.
  - Separate asynchronous error handling from completion: call `complete()` on success and `dispatch()` on failure.
  - Relocate and trim Cobble in Boot Loader, embedding the required logging classes independently of application dependencies. Project dependencies and published artifacts use the same self-contained Loader JAR.
  - Upgrade Cobble to `5.0.4` and move IDE code style configurations to `community`.
  - Add tests for MVC, Bean initialization, static resource caching, and Loader dependency isolation, plus integration cases for Jetty, Tomcat, and Undertow.

## Upgrade Notes

- `ResourceBinder.cacheControl` now accepts `CacheControl`; replace string arguments with `CacheControl.noCache()`, `noStore()`, or another policy. See [static resources](../../guides/webmvc/web/resources.md).
- Singleton `@Bean` factories and their `initMethod` callbacks now run at container startup instead of waiting for the first reference. Review external resource access in factories and initialization callbacks.
- Custom `Invoker` implementations must implement `setSkipRender()` and `isSkipRender()`. Custom `WebApiBinder` implementations must implement MVC `bindInterceptor(...)` and `addExceptionHandler(...)`. Their wrapper classes already delegate these methods.
- Extensions calling `RenderProcessor` directly must call `initInvoker(invoker)` before MVC invocation, then pass the final result to `invoke(invoker, finalResult)` instead of passing an invocation chain.
- In custom `AsyncInvocationWorker` implementations, `doWorkWhenError(...)` only handles errors; `finish(boolean)` owns completion and redispatch. See [asynchronous requests](../../guides/webmvc/j2ee/async.md) for response-output and exception-propagation limitations.
