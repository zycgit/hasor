# v5.1.1-SNAPSHOT (开发中)

开发中，尚未正式发布。本页记录 v5.1.0 之后的变化。

## 影响范围

- Boot 启动、注解扫描、Web 渲染、静态资源与健康检查

## 更新内容

- 新增
  - 统一普通应用与 Web 应用的 Boot 入口，通过 `BootExtension` SPI 扩展运行环境。
  - 将 `@Aop` 处理内置到 Core；`ConfigurationModule` 统一组织配置类、Bean 和 Web 映射扫描。
  - Web 内置返回值渲染，支持 JSON、文本及 none 模式；自动选择 JSON 库，也可传入自定义序列化实例。
  - 增加 `ResourceBinder`，支持多个资源来源、缓存校验、欢迎页和前端路由回退。
  - Boot Web 提供健康检查端点，支持关闭、修改路径和通过 Bean 扩展检查；任一检查失败时汇总为 DOWN。
- 优化
  - 渲染直接进入请求执行流程，不再依赖插件或过滤器装配；识别手动接管、异步及已提交响应，避免重复输出。
  - Action 优先于静态资源匹配，静态资源不进入 Hasor 业务过滤链。
  - 统一应用启动失败清理和关闭生命周期，扩展重定向状态码支持。

## 升级说明

- 统一启动模块为 `hasor-boot`，不再使用开发期间的 `hasor-boot-runtime`、`hasor-boot-core` 名称。
- 扫描范围统一使用 `hasor.loadPackages`，删除 Config/Web 独立的 `autoScan` 和 `scanPackages`。
- Web 容器配置迁至 `hasor.boot.web.server`、`connectors.http`，只允许引入一个 `WebServerProvider` 实现，不再通过配置选择 provider。
- 渲染默认值在 `hasor.render.defaults.objectEngine/stringEngine` 中配置；资源注册改用 `addResource`。
- `HealthCheck` 只保留 `check()`，检查名称由容器绑定信息提供，不再实现 `name()`。
