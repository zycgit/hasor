# v5.3.0（开发中）

## 影响范围

- Web、Config、Boot Loader 和文档。

## 更新内容

- 新增
  - 增加 `HandlerInterceptor` 及 `WebApiBinder.bindInterceptor(...)`，提供按注册顺序执行的前置处理，以及逆序执行的后置处理和完成回调。
  - 增加 `ExceptionHandler` 及 `WebApiBinder.addExceptionHandler(...)`，优先匹配最具体的异常类型。
  - 增加 `Invoker.setSkipRender()`、`isSkipRender()`，支持在当前请求中单向开启跳过渲染。
  - Config 增加 `WebMvcConfigurer.addInterceptors(...)` 和 `@Exception` 工厂注册，复用 Bean 的依赖注入、作用域和生命周期管理。
- 修复
  - 修复 `void` Action 的异常处理结果无法渲染的问题。
  - 修复请求结束后请求参数缓存未清理的问题。
  - 修复未匹配 Action 时读取内容类型的空指针异常。
- 优化
  - MVC 调用和异常处理先产生最终结果，再决定是否渲染；正常返回值、后置处理结果与异常处理结果共用渲染流程。
  - Web 上下文初始化时加载拦截器和异常处理器注册定义，避免每次请求重复查询容器。
  - 拆分异步任务的错误处理与结束逻辑，成功时调用 `complete()`，失败时调用 `dispatch()`；异常传播限制见异步请求文档。
  - Boot Loader 重定位并裁剪 Cobble，仅内置所需日志类，与应用版本隔离；项目依赖和发布产物统一使用自包含 Loader JAR。
  - 补充 MVC、异常处理、渲染控制及 Loader 依赖隔离测试，增加 Jetty、Tomcat、Undertow 的 MVC 集成用例。

## 升级说明

- 自行实现 `Invoker` 时需补齐 `setSkipRender()`、`isSkipRender()`；自行实现 `WebApiBinder` 时需补齐 MVC `bindInterceptor(...)` 和 `addExceptionHandler(...)`。对应包装类已提供委托实现。
- 直接调用 `RenderProcessor` 的扩展需在 MVC 调用前执行 `initInvoker(invoker)`，调用结束后通过 `invoke(invoker, finalResult)` 传入最终结果，不再传递调用链。
- 自定义 `AsyncInvocationWorker` 时，`doWorkWhenError(...)` 仅处理错误，结束与重新分发由 `finish(boolean)` 负责，避免重复调用 `complete()` 或 `dispatch()`。
- 异步请求的响应输出与异常传播限制见[异步请求](../../guides/webmvc/j2ee/async.md)。
