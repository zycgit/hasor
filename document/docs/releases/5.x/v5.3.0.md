# v5.3.0（待发布）

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>hasor-web</artifactId>
    <version>5.3.0</version>
</dependency>
```

## 更新内容

- 新增
  - 支持方法级 `@MappingTo`、可选类级公共前缀和自动扫描；同一路径可按 HTTP 方法区分，并在启动时检查冲突路由。
  - 增加 `HandlerInterceptor` 和 `WebApiBinder.bindInterceptor(...)`，前置处理按注册顺序执行，后置处理和完成回调逆序执行；Config 提供 `WebMvcConfigurer.addInterceptors(...)` 配置入口。
  - 增加 `ExceptionHandler`、`WebApiBinder.addExceptionHandler(...)` 和 `@Exception` 工厂注册，优先匹配最具体的异常类型，支持依赖注入、作用域和生命周期管理。
  - 增加 `Invoker.setSkipRender()`、`isSkipRender()`，支持跳过当前请求的结果渲染。
  - 静态资源增加 `CacheControl` 类型配置，支持缓存时长、共享/私有缓存及链式指令。
  - `@Bean` 工厂方法参数支持 `@Inject`，按名称和类型或绑定 ID 注入依赖。
- 修复
  - 修复无人引用的单例 `@Bean` 未在启动时创建、`initMethod` 未自动执行的问题。
  - 修复 `void` Action 的异常处理结果无法渲染的问题。
  - 修复请求结束后参数缓存未清理，以及未匹配 Action 时读取内容类型的空指针异常。
  - 修复统一 Boot 入口遗漏 Web 访问地址日志的问题，并正确处理实际端口、上下文路径和 IPv6 地址。
- 优化
  - 正常返回值、拦截器修改后的结果与异常处理结果共用渲染流程；拦截器和异常处理器注册在 Web 上下文初始化时加载。
  - 分离异步任务的错误处理与结束逻辑，成功时调用 `complete()`，失败时调用 `dispatch()`。
  - Boot Loader 重定位并裁剪 Cobble，内置所需日志类，与应用依赖隔离；项目依赖和发布产物统一使用自包含 Loader JAR。
  - Cobble 升级至 `5.0.4`，IDE 代码格式配置统一移至 `community` 目录。
  - 补充 MVC、Bean 初始化、静态资源缓存及 Loader 依赖隔离测试，以及 Jetty、Tomcat、Undertow 集成用例。

## 升级说明

- `ResourceBinder.cacheControl` 改为接收 `CacheControl`，原字符串调用改为 `CacheControl.noCache()`、`noStore()` 等；详见[静态资源](../../guides/webmvc/web/resources.md)。
- 单例 `@Bean` 会在容器启动时创建并执行 `initMethod`，不再等到首次被引用；检查工厂方法及初始化回调中的外部资源访问。
- 自行实现 `Invoker` 时需补齐 `setSkipRender()`、`isSkipRender()`；自行实现 `WebApiBinder` 时需补齐 MVC `bindInterceptor(...)` 和 `addExceptionHandler(...)`。对应包装类已提供委托实现。
- 直接调用 `RenderProcessor` 的扩展需在 MVC 调用前执行 `initInvoker(invoker)`，调用结束后通过 `invoke(invoker, finalResult)` 传入最终结果，不再传递调用链。
- 自定义 `AsyncInvocationWorker` 时，`doWorkWhenError(...)` 仅处理错误，结束与重新分发由 `finish(boolean)` 负责；异步输出与异常传播限制见[异步请求](../../guides/webmvc/j2ee/async.md)。
